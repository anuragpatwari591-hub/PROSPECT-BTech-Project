# 05 — Metrics

> Generated by `scripts/generate_metrics_doc.py` from `backend/app/engines/metrics.py`. Do not edit by hand.

## Commits (90 days) (`commits_90d`)

- **Definition:** Number of non-bot commits authored in the last 90 days.
- **Formula:** `count(commits where as_of − 90d < authored_at ≤ as_of and not bot)`
- **Data source:** GET /repos/{o}/{r}/commits
- **Unit:** commits
- **Interpretation:** Overall development volume. Compare against the project's own history, not other projects.
- **Limitations:** Counts only the default branch. Squash-merges collapse many changes into one commit. Page caps can truncate busy repositories (flagged in the run).

## Commit frequency (`commit_frequency_per_week`)

- **Definition:** Average non-bot commits per week over 90 days.
- **Formula:** `commits_90d / (90 / 7)`
- **Data source:** Commits endpoint
- **Unit:** commits/week
- **Interpretation:** Pace of change on the default branch.
- **Limitations:** Same as commits_90d; commit granularity differs by team habit.

## Active weeks ratio (`active_weeks_ratio`)

- **Definition:** Share of the last 13 weeks that had at least one non-bot commit.
- **Formula:** `weeks_with_commits(13) / 13`
- **Data source:** Commits endpoint
- **Unit:** ratio 0–1
- **Interpretation:** Regularity of activity; low values indicate bursty or stalled work.
- **Limitations:** A project that commits once a week and one that commits 100 times a week score the same.

## Activity trend (`activity_trend_pct`)

- **Definition:** Change in commit rate in the last 30 days relative to the preceding 60 days.
- **Formula:** `(c30 − c60/2) / (c60/2) × 100, capped to [−100, +100]; null if both are 0`
- **Data source:** Commits endpoint
- **Unit:** %
- **Interpretation:** Negative = recent slowdown; positive = acceleration.
- **Limitations:** Sensitive to holidays and release cycles; one month is a short baseline.

## Days since last commit (`days_since_last_commit`)

- **Definition:** Days between the analysis time and the most recent non-bot commit in the collected window.
- **Formula:** `as_of − max(authored_at)`
- **Data source:** Commits endpoint
- **Unit:** days
- **Interpretation:** Recency of development.
- **Limitations:** Null if no commits in the collection window (reported as window length).

## Open issues (`open_issues`)

- **Definition:** Number of currently open issues (pull requests excluded).
- **Formula:** `count(issues where state = open)`
- **Data source:** GET /repos/{o}/{r}/issues?state=open
- **Unit:** issues
- **Interpretation:** Size of the backlog. Popular projects naturally have more issues.
- **Limitations:** Not normalised by project size; truncated when above the page cap.

## Issues opened (90 days) (`issues_opened_90d`)

- **Definition:** Issues created in the last 90 days.
- **Formula:** `count(created_at in window)`
- **Data source:** Issues endpoint
- **Unit:** issues
- **Interpretation:** Incoming demand / defect reports.
- **Limitations:** Depends on the project's use of GitHub Issues.

## Issues closed (90 days) (`issues_closed_90d`)

- **Definition:** Issues closed in the last 90 days.
- **Formula:** `count(closed_at in window)`
- **Data source:** Issues endpoint
- **Unit:** issues
- **Interpretation:** Maintainer throughput on the backlog.
- **Limitations:** Closing as 'won't fix' counts the same as fixing.

## Issue close ratio (`issue_close_ratio_90d`)

- **Definition:** Issues closed divided by issues opened in the last 90 days.
- **Formula:** `issues_closed_90d / issues_opened_90d; null if none opened`
- **Data source:** Issues endpoint
- **Unit:** ratio
- **Interpretation:** ≥ 1 means the backlog is shrinking; < 1 means it is growing.
- **Limitations:** Closed issues may have been opened before the window.

## Median open issue age (`median_open_issue_age_days`)

- **Definition:** Median age of currently open issues.
- **Formula:** `median(as_of − created_at) over open issues`
- **Data source:** Issues endpoint
- **Unit:** days
- **Interpretation:** Higher values suggest issues are not being triaged.
- **Limitations:** Long-lived feature requests inflate this legitimately.

## Median issue resolution time (`median_issue_resolution_days`)

- **Definition:** Median time from creation to closure for issues closed in the last 90 days.
- **Formula:** `median(closed_at − created_at)`
- **Data source:** Issues endpoint
- **Unit:** days
- **Interpretation:** Responsiveness to reported issues.
- **Limitations:** Survivor bias: only closed issues are measured.

## Open pull requests (`open_prs`)

- **Definition:** Number of currently open pull requests.
- **Formula:** `count(state = open)`
- **Data source:** GET /repos/{o}/{r}/pulls?state=open
- **Unit:** PRs
- **Interpretation:** Review queue size.
- **Limitations:** Includes drafts.

## PRs merged (90 days) (`prs_merged_90d`)

- **Definition:** Pull requests merged in the last 90 days.
- **Formula:** `count(merged_at in window)`
- **Data source:** Pulls endpoint
- **Unit:** PRs
- **Interpretation:** Integration throughput.
- **Limitations:** Projects that push directly to main will show low values.

## Median PR turnaround (`median_pr_turnaround_days`)

- **Definition:** Median time from PR creation to merge for PRs merged in the last 90 days.
- **Formula:** `median(merged_at − created_at)`
- **Data source:** Pulls endpoint
- **Unit:** days
- **Interpretation:** Longer turnaround is associated with review bottlenecks (Gousios et al., 2014 study merge time factors).
- **Limitations:** Excludes PRs closed without merge; drafts opened early inflate it.

## PR turnaround trend (`pr_turnaround_trend_pct`)

- **Definition:** Change in median turnaround for PRs merged in the last 30 days versus the preceding 60 days.
- **Formula:** `(m30 − m60) / m60 × 100, capped to [−100, +300]`
- **Data source:** Pulls endpoint
- **Unit:** %
- **Interpretation:** Positive = reviews are getting slower.
- **Limitations:** Needs at least 3 merged PRs in each period, otherwise null.

## Stale open PR ratio (`stale_open_pr_ratio`)

- **Definition:** Share of open PRs not updated for more than 30 days.
- **Formula:** `count(open and as_of − updated_at > 30d) / open_prs`
- **Data source:** Pulls endpoint
- **Unit:** ratio 0–1
- **Interpretation:** Abandoned or blocked review work.
- **Limitations:** Null when there are no open PRs.

## Median PR size (`median_pr_size_lines`)

- **Definition:** Median of additions + deletions over a sample of recently merged PRs.
- **Formula:** `median(additions + deletions)`
- **Data source:** GET /repos/{o}/{r}/pulls/{n} (sampled)
- **Unit:** lines
- **Interpretation:** Large PRs are harder to review.
- **Limitations:** Sample of the most recent merged PRs only (PR_DETAIL_SAMPLE); generated files and lockfiles inflate size.

## Active contributors (90 days) (`contributors_90d`)

- **Definition:** Distinct non-bot commit authors in the last 90 days.
- **Formula:** `count(distinct author_key)`
- **Data source:** Commits endpoint
- **Unit:** people
- **Interpretation:** Breadth of the active team.
- **Limitations:** One person with two e-mails may count twice when accounts are unlinked.

## Top contributor share (`top_contributor_share`)

- **Definition:** Share of the last 90 days' non-bot commits made by the single most active author.
- **Formula:** `max(commits_by_author) / commits_90d`
- **Data source:** Commits endpoint
- **Unit:** ratio 0–1
- **Interpretation:** High values mean knowledge and progress depend on one person.
- **Limitations:** Commit counts are a proxy for contribution; reviews, design and triage are invisible.

## Commit-share bus factor (estimate) (`bus_factor_estimate`)

- **Definition:** Smallest number of authors who together made at least 50% of non-bot commits in the last 90 days.
- **Formula:** `min k such that sum of top-k author commit counts ≥ 0.5 × commits_90d`
- **Data source:** Commits endpoint
- **Unit:** people
- **Interpretation:** 1 = a single person carries half the work. A simplified heuristic, NOT the file-ownership truck-factor algorithm of Avelino et al. (2016).
- **Limitations:** Ignores code ownership and expertise; short window.

## Releases (365 days) (`releases_365d`)

- **Definition:** Published, non-draft releases in the last year.
- **Formula:** `count(published_at within 365 days)`
- **Data source:** GET /repos/{o}/{r}/releases (first 100)
- **Unit:** releases
- **Interpretation:** Delivery cadence for projects that use GitHub Releases.
- **Limitations:** Many projects tag versions without GitHub Releases; then release metrics are not applicable.

## Days since last release (`days_since_last_release`)

- **Definition:** Days since the most recent published release.
- **Formula:** `as_of − max(published_at)`
- **Data source:** Releases endpoint
- **Unit:** days
- **Interpretation:** Delivery recency.
- **Limitations:** Null when the project has never published a GitHub Release.
